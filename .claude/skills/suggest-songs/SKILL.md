# suggest-songs

`src/data/songs.json` の傾向を読んで、次に足すと嬉しい曲を提案するスキル。
**推薦して終わりではなく、選ばれた曲を `manage-songs` で実際に追加するところまで**が仕事。

## 進め方

### 1. プールの傾向を掴む(必ず最初に)

```sh
node .claude/skills/suggest-songs/scripts/profile.mjs
```

総数 / mastery内訳 / 複数曲あるアーティスト / タグ分布 / 1曲だけのアーティスト が出る。
**複数曲あるアーティストほど好みが強く出ている**ので、その周辺(同アーティストの別曲、
同系統の作家)は当たりやすい。

重複チェック用の全曲一覧はこれ:

```sh
node .claude/skills/suggest-songs/scripts/profile.mjs --titles
```

### 2. 候補を選ぶ

ユーザーの指定(アーティスト名・ジャンル・「夏っぽい」等のテーマ・曲数)に沿って選ぶ。
指定がなければ **ボカロ / J-POP / J-ROCK** からバランスよく。

選ぶときの基準:

- **既存と重複しない**(1 の一覧と必ず突き合わせる。表記ゆれも見る)
- **プールの傾向に沿う**: このプールはボカロが主軸で、アニソン・J-POP が続く。
  弾き語り/メドレーで映える有名曲が中心
- **偏りすぎない**: 同一アーティストばかりにせず、時代(黎明期〜近年)や
  作風を散らす。ユーザーが特定アーティストを指定した場合はその限りではない
- 既に多いアーティスト(Deco*27・ヨルシカ等)は「まだ入っていない代表曲」を狙う

### 3. 提示する

グループ分け(アーティスト別 / 時代別 / テーマ別など、その時に自然な軸)して、
曲名とアーティスト、必要なら一言(代表曲・タイアップ等)を添える。
**mastery は勝手に決めず、ユーザーに選んでもらう**(弾ける / 練習中 / 覚えたい)。

### 4. 選ばれた曲を追加する

ユーザーが曲と mastery を指定したら **`manage-songs` スキル**で追加する。
その際:

- **アーティスト名・正式タイトルが少しでも怪しければ Web 検索で確認する**。
  同名異曲や表記ゆれ(「ずぅっと」→「ずうっといっしょ！」、「超絶可愛い」→
  「#超絶かわいい」等)が頻出する。ユーザーの入力表記をそのまま鵜呑みにしない
- 確認した結果ユーザーの認識と違ったら、**正式表記で登録した上でその旨を伝える**
- タグは既存の流儀に合わせる(`ボカロ` / `アニソン` + 作品名 など)
- `bpm` / `key` は埋めない(null のまま)

## サジェストの引き出し(参考)

プールの傾向から見て当たりやすい方向:

- **同アーティストの未収録曲** — profile の上位アーティストの代表曲で漏れているもの
- **同系統のボカロP** — 例: wowaka / ハチ / じん が好きなら近い年代・作風の作家
- **アニメタイアップ** — アニソンタグが厚いので、近年の主題歌は刺さりやすい
- **テーマ指定** — 「夏」タグのように季節・場面で括る
- **世代を遡る/下る** — 黎明期の名曲(千本桜・メルト世代)や最新ヒットで幅を出す

迷ったら、ユーザーがどのアーティストを何曲持っているかを見せて
「この辺を深掘りする?別ジャンルを開拓する?」と聞くのが早い。
